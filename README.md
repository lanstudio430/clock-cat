# 工時貓 Clock Cat

月行事曆工時記錄：原定與實際上下班、假別、週合計與加班時數。可安裝到手機主畫面，像 App 一樣使用，離線也能看與記。

```
手機 / 電腦 ── GitHub Pages（網頁前端，PWA）── fetch ──► Apps Script（API）──► Google Sheets
                     └ 本機快取與待同步佇列
```

- 可切換年份、月份，一週從星期一開始
- 點擊日期格子可新增、編輯、刪除原定與實際上下班時間，以及假別（例假、休假、國定假日）
- 日曆以紅字顯示上下班時間：有填實際時間就顯示實際，否則顯示原定
- 每週右側顯示該週上班時數，最下方顯示週合計加總，只計算當月
- 可填寫每個月的應上班時數，填寫後顯示加班時數（週合計加總減應上班時數）
- 儲存時先更新畫面，再於背景同步到試算表；離線時變更會留在手機上，恢復連線後自動送出
- **薪資試算：** 每個月各自設定本薪（或工讀生時薪）、加項與扣項，常用類別一鍵加入；自動算出加班費、假日加給與預估實領薪資，改本薪不影響更早的月份；規則見下方「薪資試算」
- 介面是「貼紙手帳」風格，貓咪會依本月進度說話；設計規格見 [design/README.md](design/README.md)

## 專案結構

| 路徑 | 用途 |
| --- | --- |
| `apps-script/Code.gs` | 後端：驗證密鑰、讀寫試算表，以 JSON 回應 |
| `web/` | 前端原始碼：Svelte 5 + TypeScript，用 Vite 建置 |
| `web/src/lib/` | 工時與薪資的計算規則（`calc.ts`、`pay.ts`）、離線快取與同步佇列、API |
| `web/src/components/` | 畫面元件（頂列、月份標籤、本月卡、日曆、編輯面板、連線設定…） |
| `docs/` | **建置結果**，GitHub Pages 直接發布這個資料夾；不要手動修改 |
| `design/` | 圖示原圖、設計稿與設計規格 |
| `scripts/` | 建置工具：芫荽字型裁切、產生 Service Worker |
| `tests/unit/`、`tests/e2e/` | 單元測試（Vitest）與瀏覽器流程測試（Playwright） |

## 安裝

### 1. 後端：Apps Script

1. 到 [Google Sheets](https://sheets.new) 用**個人 Gmail**建立一份新的試算表。
2. 點選「擴充功能 → Apps Script」，把預設的 `Code.gs` 內容換成 `apps-script/Code.gs`。
3. 在編輯器上方的函式選單選 `setupApiKey`，按「執行」並完成授權。
4. 開啟「執行記錄」，複製 `API_KEY:` 後面那串密鑰，先暫存起來。
5. 點選「部署 → 新增部署作業」，類型選「網頁應用程式」：
   - 執行身分：我
   - 誰可以存取：**任何人**
6. 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

第一次讀寫時會自動建立「班表」與「月設定」工作表。

「任何人」是必要的：網頁在另一個網域，瀏覽器沒辦法帶著 Google 登入狀態呼叫。安全性靠密鑰：每個請求都要帶正確的密鑰，沒帶或不符一律拒絕，也不會回傳任何資料。

修改 `Code.gs` 後，需到「部署 → 管理部署作業 → 編輯 → 版本：新版本」重新部署，網址才會套用新程式。

換密鑰：到「專案設定 → 指令碼屬性」刪掉 `API_KEY`，再執行一次 `setupApiKey`，然後在每台裝置的設定裡貼上新密鑰。

### 多位使用者

只要部署一次。放著 `Code.gs` 的這份試算表是**主控試算表**：`setupApiKey` 產生的密鑰是**管理員密鑰**，讀寫主控試算表自己的資料；其他使用者各有一份試算表和自己的密鑰，彼此讀不到對方的資料。

第一次啟用多使用者時，在 Apps Script 編輯器執行一次 `setupUsers`：它會在主控試算表建立「使用者」工作表，之後重新開啟試算表會出現「工時貓」選單。

這時會跳出授權視窗，多要一項「查看、編輯、建立及刪除所有 Google 雲端硬碟檔案」的權限：在 App 裡建立使用者時，新的試算表一開始在雲端硬碟根目錄，要用它移到主控試算表所在的資料夾。程式只用它查主控試算表的資料夾、移動新建的試算表；Google 的授權沒有更窄、又能做到這件事的選項。權限可以在 Apps Script 左側「總覽」的「專案 OAuth 範圍」查看，或到 [Google 帳戶的第三方連結](https://myaccount.google.com/connections) 查看與撤銷。

新增使用者有兩種方式：

- **在 App 裡（管理員）：** 用管理員密鑰連線，打開設定 →「多位使用者」→「建立新使用者」，輸入名稱。後端會在主控試算表所在的資料夾開一份「工時貓 - 名稱」試算表，產生密鑰，並把這位使用者加到這台裝置。主控試算表在雲端硬碟根目錄時，新的也會在根目錄；沒有那個資料夾的編輯權時，新的會留在根目錄，畫面上會註明。要在其他裝置使用時，密鑰可以在 App 裡編輯那位使用者（按眼睛圖示顯示），或在「使用者」工作表裡找到。
- **自己開試算表：** 開一份新的 Google Sheets（放在部署者的雲端硬碟，或用「編輯者」權限分享給部署者），在主控試算表的「使用者」工作表加一列：名稱、密鑰留空、試算表 ID 或整個網址，再從「工時貓 → 補上使用者密鑰」產生密鑰。

| 名稱 | 密鑰 | 試算表 |
| --- | --- | --- |
| 小華 | （自動產生） | `1AbC…` 或 `https://docs.google.com/spreadsheets/d/1AbC…/edit` |

在其他裝置使用某位使用者：設定 →「加入使用者」，貼上同一個 Apps Script 網址和那位的密鑰。同一台裝置可以加好幾位，從頂列的頭像切換；每位的快取、待同步變更和薪資設定各自分開，離線時記下的變更會等切回那位時再送出。

停用某位使用者：刪掉「使用者」工作表裡那一列，那把密鑰就失效；試算表本身不會被刪除。密鑰至少要 16 個字元，太短的列會被略過。

### 2. 前端：GitHub Pages

1. 把專案推到 GitHub（公開 repo）。
2. 到 repo 的「Settings → Pages」，Source 選「Deploy from a branch」，Branch 選 `main`、資料夾選 `/docs`。
3. 等一兩分鐘，網址是 `https://<帳號>.github.io/clock-cat/`。

程式碼是公開的，但網址與密鑰都不在程式碼裡，資料也不在 repo 裡。

### 3. 第一次使用

1. 開啟網站，會跳出「連線設定」，貼上 Apps Script 的網址與密鑰後儲存。
2. 設定只存在這台裝置的瀏覽器裡，每台裝置各設定一次。

#### 安裝到 iPhone

1. 用 Safari 開啟網站，點「分享 → 加入主畫面」。
2. 從主畫面開啟「工時貓」，會是全螢幕、沒有網址列。
3. iPhone 的主畫面 App 與 Safari 的儲存空間是分開的，所以要在主畫面 App 裡再貼一次網址與密鑰（點右上角的齒輪）。

Android 的 Chrome 與電腦的 Chrome、Edge 也能安裝：網址列旁會出現安裝按鈕。

## 離線與同步

- 每個月份的資料會快取在裝置上，開啟時先顯示快取，再於背景更新；一次會取回前後各一個月，切換月份不用等。
- 儲存、刪除、修改應上班時數時，畫面立刻更新，變更先排進佇列再依序送出。
- 本月卡右上角的印章顯示同步狀態：已同步、同步中、離線・N 筆待同步、顯示上次的資料，或連線設定的問題。
- 沒有網路時，變更留在佇列裡，恢復連線、回到 App 或點印章重試時送出。
- 伺服器拒絕某筆變更時（例如資料不合規則），該筆會被丟棄，畫面底部的紅色提示說明原因，畫面回到試算表裡的內容。
- 試算表永遠是準的：同步完成後，畫面以試算表內容為準。
- 換成另一份試算表（更改網址）時，舊的快取與尚未送出的變更會清掉。

## 開發

需要 Node.js 22 以上；瀏覽器測試會用電腦上已安裝的 Google Chrome。

```
npm install
npm run dev        # 本機開發：http://localhost:5173
npm run build      # 建置到 docs/
npm run check      # 型別檢查
npm test           # 單元測試（含 Code.gs 與字型檢查）
npm run test:e2e   # 瀏覽器流程測試（手機與桌面版面）
npm run fonts      # 介面中文字有增減時，重新裁切芫荽
```

- **發布：** 執行 `npm run build`，把 `docs/` 跟原始碼一起提交、推送，GitHub Pages 就會更新。`docs/sw.js` 也是建置產生的，版本號跟著內容變，使用者下次開啟就會拿到新版。
- **字型：** 芫荽只保留介面用到的字。改了介面文字後執行 `npm run fonts`；忘記的話，單元測試會列出漏掉的字。中文註解請寫在獨立的一行，整行註解不會被算進字型。
- **本機開發的資料：** `npm run dev` 一樣要在連線設定貼上 Apps Script 網址與密鑰，資料直接讀寫你的試算表。
- **測試怎麼跑後端：** 單元與瀏覽器測試都在 Node 裡執行真正的 `Code.gs`，搭配記憶體裡的假試算表，不會碰到你的資料。
- **授權：** 芫荽與 Nunito 是 SIL Open Font License（授權檔在 `web/public/fonts/`）；Font Awesome 圖示是 CC BY 4.0，授權說明保留在每個 SVG 裡。

## 薪資試算

日曆下方的薪資卡會用每個月的班表自動試算加班費和預估實領。設定存在試算表的「薪資設定」工作表，換手機也會同步，離線時先存在手機上。**試算僅供參考，實際金額以公司薪資單為準。**

### 三個層次

1. **常用類別**（薪資卡的「常用類別」）：集中管理經常出現的加項與扣項，預設有加項「津貼、獎金、加給」，扣項「勞保費、健保費、職工福利金、勞工自提退休金」。每個類別可以設預設的方式（金額或比例）和預設值，例如職工福利金預設 0.5%。可以改名、刪除、新增，也能還原成預設。
2. **每月的薪資設定**（薪資卡的「編輯本月」）：身分（正職／工讀生）、本薪或時薪、時薪的進位方式，加上這個月的**加項**與**扣項**。點「快速加入」的類別就會帶入名稱和預設值，游標直接跳到金額；每個月特別的項目用「自訂加項」「自訂扣項」，隨時能改或刪。
3. **薪資卡**：把這個月的設定和班表算出來，加項（綠色）與扣項（紅色）分開列出，最上面是預估實領。

### 每個月各自的設定，更早的月份不受影響

- 設定是**從這個月起生效**：改了 12 月的本薪，11 月和更早的月份不會變。
- 沒有自己設定的月份，會沿用**比它早、最近的一個月**的設定（卡片上會寫「沿用 N 月的設定」）；按「編輯本月」存檔後，這個月就有自己的設定。
- 每個項目有「每月沿用」與「只限本月」兩種：從常用類別加入的預設是每月沿用，自訂的預設只限本月（例如年終獎金、補發差額），點一下就能切換。沿用時只會帶過去「每月沿用」的項目。
- 比所有設定都早的月份還沒有設定，不會倒回去套用之後才設定的內容；按「設定這個月」時會帶入最近的設定當草稿，省得重填。
- 「清除本月設定」（在視窗最底下）會刪掉這個月自己的設定，改回沿用前面的月份。

### 設定項目

- **身分：** 正職（月薪制）或工讀生（時薪制）。
- **本薪／時薪：** 正職填每月本薪；工讀生填時薪（會對照當年基本工資提醒，2026 年 196 元、2027 年起 205 元）。
- **時薪的進位方式（正職）：** 時薪 = 本薪 ÷ 30 ÷ 8，除不盡時可選不進位、四捨五入到整數、無條件進位到整數。選「不進位」時，畫面上的時薪會寫成 `122.9167…`（顯示四位小數，後面還有就加「…」），但計算用的是完整的數字，不是顯示出來的那幾位。
- **金額的進位方式：** 時薪乘出來的加班費、假日加給、休假日出勤、工讀生工資，以及比例的項目，每一行金額都照這個設定處理：**不進位**（保留到小數第二位）、**四捨五入**到整數、**無條件進位**到整數。預設是四捨五入。
- **加項、扣項：** 名稱，加上「金額」或「比例」（本薪的百分比；工讀生是當月工資的百分比）。點金額旁邊的「NT$／%」可以切換。

### 正職怎麼算

月薪制、變形工時：本薪已經包含每月的應上班時數，超過的才算加班費。

| 情況 | 計算 |
| --- | --- |
| 平日加班 | （平日時數 − 應上班時數）× 時薪 × 1.34；平日時數是沒有假別的日子，加上國定假日的全部時數 |
| 國定假日出勤 | 加發一日工資（8 小時 × 時薪），不論實際做幾小時；時數全部算進平日時數，超過 8 小時的部分跟著平日加班一起算加班費 |
| 休假（休息日、空班日）出勤 | 每天各自計算：前 2 小時 × 1.34、第 3 至 8 小時 × 1.67、第 9 小時起 × 2.67；依實際工時計算（2018 年修法後不再「做一給四」） |
| 例假出勤 | 加發一日工資；超過 8 小時的部分，每天前 2 小時 × 1.34、其後 × 1.67 |

- 休假、例假的時數另外計價，不算進平日時數，所以不會重複算。
- 沒有填應上班時數時無法判斷加班，薪資卡會提醒；時數還不到應上班時數時不扣薪。
- 日曆底部的「加班時數」維持「週合計加總 − 應上班時數」，包含休假與例假的時數；薪資卡的加班費只算上表的平日加班。

### 工讀生怎麼算

月薪 = 時薪 × 當月出勤工時，所有時數一視同仁，假別不加成。這是簡化算法：依勞基法，工讀生每日超過 8 小時、休息日與國定假日出勤也應該有加給，目前沒有計入。

### 金額的進位

兩個進位設定是分開的：先決定時薪要不要進位，再用那個時薪去乘；乘出來的每一行金額再依「金額的進位方式」處理。例如本薪 29,500、時薪不進位、加班 10 小時：10 × 122.9166… × 1.34 = 1,647.0833…，不進位顯示 1,647.08、四捨五入 1,647、無條件進位 1,648。

加項、扣項與實領都用處理好的各行相加（以「分」為單位，不會有 0.1 + 0.2 的誤差），所以畫面上看到的數字一定加得起來。

### 每年要更新的資料

基本工資（`web/src/lib/pay.ts` 的 `MINIMUM_WAGES`）每年第三季公告後新增一列，目前有 2026 年（月薪 29,500、時薪 196）與 2027 年（月薪 30,900、時薪 205，2027/01/01 起）。只用在提醒，不影響計算。

## 時間格式

時間以小數小時表示：`09:30` 是 `9.5`，`21:30` 是 `21.5`；整點在日曆上補零，例如 `09`。下拉選單可選 06 到 21 點，分鐘可選 `0`、`.25`、`.5`、`.75`。

上下班時間需成對選擇，將「時」選回 `--` 即可清除。一天可以只填原定、只填實際、只填假別，或同時填寫。

## 計算規則

- 週合計以日曆上顯示的時間計算：有填**實際**時間就用實際，沒填就用**原定**。
- 週合計為下班減上班，**不扣除休息時間**：`09` 到 `21.5` 算 12.5 小時。
- 週合計只計算當月日期：跨月的週，其他月份的日期在畫面上留白，時數也不計入。
- 週合計加總是當月所有週合計相加，也就是月上班總時數。
- 加班時數為週合計加總減應上班時數，可能是負數；未填應上班時數時不顯示。
- 下班時間必須晚於上班時間，不支援跨夜班。
- 每天只能有一段原定與一段實際上下班時間。

## 資料格式

「班表」工作表的每一列代表一天，所有欄位都是純文字：

| 日期 | 原定上班 | 原定下班 | 實際上班 | 實際下班 | 假別 |
| --- | --- | --- | --- | --- | --- |
| 2026-11-02 | 9 | 21.5 | 9.25 | 21.5 | |
| 2026-11-08 | | | | | 例假 |

「月設定」工作表的每一列代表一個月：

| 月份 | 應上班時數 |
| --- | --- |
| 2026-11 | 176 |

「薪資設定」工作表由 App 寫入，不需要手動編輯。第二欄是 JSON 文字，格式不對的列 App 會略過：

| 項目 | 內容 |
| --- | --- |
| `catalog` | 常用類別（只有自訂過才會有這一列） |
| `month:2026-11` | 2026 年 11 月自己的薪資設定；沒有這一列的月份沿用前面的月份 |

直接編輯工作表時請維持相同格式，日期必須是 `yyyy-MM-dd`、月份必須是 `yyyy-MM`，否則行事曆讀不到該列。

## 升級

### 從 v2.1.x 升級（加入多位使用者）

原本的試算表直接當主控試算表，**資料不用搬**，原本的網址和密鑰照常使用（這把密鑰就是管理員密鑰）。

1. 把新的 `apps-script/Code.gs` 貼到 Apps Script 取代舊的。
2. 在編輯器執行一次 `setupUsers`，建立「使用者」工作表，並在跳出的視窗允許新的雲端硬碟權限（見上面「多位使用者」）。執行記錄出現「補上了 0 個密鑰」就是成功。沒做這一步，在 App 裡建立使用者會失敗。
3. 「部署 → 管理部署作業 → 編輯 → 版本：新版本」重新部署，網址不會變。
4. 推送新的 `docs/`。手機上原本的連線設定會變成第一位使用者「我」，快取、待同步變更和薪資設定都沿用原本的位置，不會搬動。

忘了重新部署也不會壞：自己的月曆照常運作，只是設定裡會提示後端還沒更新，不能在 App 裡建立使用者。

### 從 v2.0.0 升級（加入薪資試算）

1. 把新的 `apps-script/Code.gs` 貼到 Apps Script 取代舊的（多了薪資設定的讀寫：`getPayData`、`savePayCatalog`、`savePayMonth`）。
2. 「部署 → 管理部署作業 → 編輯 → 版本：新版本」重新部署，網址不會變，密鑰也不用換。
3. 推送新的 `docs/`，手機上的連線設定、快取和待同步變更都會沿用。

忘了重新部署也不會壞：月曆照常運作，只是薪資設定只存在這台裝置，薪資卡上會寫明原因；重新部署後再開啟，本機的設定會自動送到試算表。

### 從 v1.1.0 升級

前端換成 Svelte 與新介面，`Code.gs` 沒有改，Apps Script 不用重新部署。推送新的 `docs/` 之後，手機上原本的連線設定、快取和待同步變更都會沿用。

### 從 v1.0.0 升級

v1.0.0 是直接由 Apps Script 提供網頁的版本。升級時：

1. 沿用原本的試算表，把 `Code.gs` 換成新版，並刪掉專案裡的 `Index` 檔案。
2. 照上面的步驟執行 `setupApiKey`，並把部署的存取權限改成「任何人」，重新部署新版本。
3. 試算表裡的資料不需要轉換。

更早的版本只有「日期、上班、下班、假別」四欄。第一次讀取時會自動轉換：舊時間轉成小數並放入實際上下班欄位，原定時間留空。舊資料如果超出 06 到 21 點的範圍或不是整刻鐘，編輯時需要重新選擇；舊的跨夜班不會計入週合計，也需要重新填寫。
